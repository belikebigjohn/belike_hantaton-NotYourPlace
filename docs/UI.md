# Интерфейс

Frontend — React, Vite, TypeScript и CSS Modules. Палитра и композиция следуют референсу: графитовый фон, электрический синий, светлый документ и небольшой коралловый акцент. На компьютере приложение показано в вертикальной рамке рядом с краткой последовательностью шагов; на телефоне занимает весь экран. Главный экран содержит локальную растровую иллюстрацию вечернего города. Кадр показан целиком в пропорции 3:2, без поворота и случайной обрезки. Рабочие экраны остаются интерактивными.

Пользователь проходит камеру общего плана, камеру номера, проверку результатов, место и время, редактирование проекта обращения, скачивание пакета и инструкцию подачи. История открывает детали каждого обращения. Состояние отправки меняет только пользователь.

`api.ts` содержит типизированный клиент с cookie сессии. Данные черновика и выбранные файлы сохраняются в IndexedDB; после перезагрузки можно продолжить. Сеть и камера не блокируют просмотр имеющихся материалов; ошибки объясняют следующее действие. Камера освобождает MediaStream при выходе. Видеопоток не отправляется на сервер. Фотографии отправляются только после выбора двух кадров для анализа.

Неизвестный результат называет конкретные обозначения: «Проверьте знак „Парковка“ и табличку „Инвалиды“ на общем фото». Интерфейс не сообщает о виновности, законности парковки или вероятности штрафа. Пользователь подтверждает сведения и время наблюдения. Текст предупреждения об ответственности согласован с законом № 59-ФЗ, ч. 2 ст. 16.

Размеры зон нажатия 44–57 px, фокус видимый, текстовые подписи и подписи иконок присутствуют, есть переход к содержимому. Анимация ограничена обратной связью и индикатором ожидания. Safe area учитывается на мобильном экране.

Локальный запуск: `cd frontend; npm install; npm run dev` (API проксируется на порт 8000). Проверка: `npm run build`, `npm run typecheck`, `npm test`. Открыть `/` на порту 5173.

## Проверка фотографий и вариантов номера

Экран проверки показывает замечания к качеству отдельно для общего плана и снимка номера. У каждой группы есть действие «Переснять», которое возвращает к соответствующей камере. Пустой список замечаний не превращается в заявление о пригодности доказательства.

Распознавание запускается отдельно на общем и крупном фото. Когда на одном снимке найдено несколько непустых вариантов, пользователь выбирает нужный автомобиль в списке именно этого снимка. Чтение и выбранная рамка сохраняются в отдельном `analysis.plate_review`; машинные `plates_by_photo` и `plate_comparison` остаются неизменными. После выбора или ручного изменения номера подтверждение сверки фотографий запрашивается заново. Изменение места/времени снимает подтверждение места/времени; изменение текста обращения или данных заявителя снимает финальное подтверждение.

Перед созданием первого обращения клиент отдельно устанавливает сессию через `/api/health`. Идентификатор попытки создания сохраняется в локальном черновике, передаётся в `Idempotency-Key` и остаётся неизменным при повторе после ошибки сети. После успешного создания или повторного получения существующей записи применяются актуальные поля черновика. Пустой черновик после удаления записи не записывается заново в локальное хранилище.

## Мобильная доводка

Основная работающая поверхность — Operate: быстро выполнить фиксацию на улице. Тёмный графит, синий акцент и исходный визуальный характер сохранены. Главная иллюстрация заменена на локальный PNG с согласованной перспективой. Все основные и вторичные CTA используют одинаковую центрированную группу текста и иконок; длинные подписи переносятся внутри группы.

На экране проверки каждый снимок имеет собственное поле номера и варианты с подписью источника. Жёлтая рамка обозначает номер на общем плане, розовая — на крупном, белые пунктирные рамки — дорожные знаки. Дополнительные номера шага, подписи полей и текстовые подписи рамок позволяют понять смысл без различения цвета. Толщина рамок фиксирована в экранных пикселях, тёмный внешний контур не даёт им исчезать на светлой фотографии. Подпись в SVG удерживается около 13 экранных пикселей при изменении размера превью.

Текст точно называет пару 6.4 + 8.17. Обнаружение пары на снимке не объявляется выводом о законности парковки. Сравниваются нормализованные подтверждаемые человеком номера на обоих фото. Несовпадение или пустое поле блокирует продолжение. Старые записи с распознаванием только одного фото не считаются совпадением: оба поля требуют повторной проверки или ручного ввода. `report.plate` получается из совпавших значений, а не из молчаливого выбора более уверенного чтения.

### Микровзаимодействия

Замысел движения: коротко подтвердить появление нового кадра и завершение подготовки пакета; не задерживать переход к следующему действию. Новый кадр получает однократный световой отклик 220 мс, успешный пакет — ограниченный отклик отметки 380 мс. Сообщение появляется за 180 мс; кнопки отвечают изменением яркости и нажатием. Длительная проверка показывает неопределённое ожидание, а не выдуманный процент. При `prefers-reduced-motion` пространственные и вспышечные эффекты отключаются, текстовые подтверждения сохраняются. Основные инструкции не скрываются у повторных пользователей.

Диагностика по восьми пунктам навыка microinteractions (экспертная проверка кода, не пользовательское исследование):

| Пункт | Найдено до доводки | Исправление и текущее состояние |
|---|---|---|
| Явный доступный триггер | Основные действия видны | Сохранено; зоны нажатия от 44 px |
| Видимое состояние действия | Неясно, к какому снимку относится результат | Источник указан в каждом поле, рамке и варианте; несовпадение видно текстом |
| Простые предсказуемые правила | CTA выровнены по-разному, значение статуса знака неясно | Единая группа CTA; знак назван точно; несовпадение номеров блокирует переход |
| Немедленная обратная связь | Отклик есть, задержка на устройстве не измерена | Синхронные состояния нажатия и ожидания; требование менее 100 мс остаётся неизмеренным |
| Соразмерная обратная связь | Новый кадр и завершение пакета недостаточно различимы | Короткий отклик кадра, отдельная отметка готовности, без блокирующей анимации |
| Поведение при повторном использовании | Есть сохранённый черновик | Возврат к черновику сохранён, важные подсказки остаются доступными |
| Отсутствие скрытых режимов | Режим камеры виден по подписи | Сохранено; источник снимка и отдельная ручная проверка явно разделены |
| Понятность первого использования | Неясный статус «обозначение», один номер для двух фото | Точная подпись пары знаков, отдельные поля и проверка совпадения |

Исходная оценка по этой диагностике — 4/8 выполненных пунктов, 5/10. После исправлений — 7/8, 9/10; неподтверждённым остаётся пункт о пороге времени отклика на физическом телефоне. Настоящие iOS/Android, уличная яркость и исследование со старшими пользователями остаются отдельной проверкой.
