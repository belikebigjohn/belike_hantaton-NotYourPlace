# Ubuntu: gosdyma.ru

При переходе со второго фото на проверку приложение отправляет оригиналы на `POST /api/reports/{id}/photos`. Два снимка могут занимать до 30 МБ. FastAPI допускает до 32 МБ на запрос, но Nginx по умолчанию может отклонить тело раньше приложения. Тогда браузер получает HTML с кодом 413, а прежний интерфейс показывал общее «Не удалось сохранить данные». Другой возможный отказ после смены домена — 403, если переменная `ALLOWED_ORIGINS` на сервере всё ещё содержит только старый адрес. Точный код отказа на текущем сервере следует посмотреть в Network браузера или журнале Nginx.

1. В `.env` на Ubuntu добавьте `https://gosdyma.ru` в `ALLOWED_ORIGINS`, сохранив нужные локальные адреса и другие действующие домены. Перезапустите службу приложения, чтобы она прочитала переменную.
2. В блоке `server` Nginx для `gosdyma.ru` задайте `client_max_body_size 32m;`. Проверьте конфигурацию `sudo nginx -t` и затем примените `sudo systemctl reload nginx`. Если перед Nginx есть ещё один прокси, проверьте его лимит отдельно.
3. Проверьте права записи пользователя службы в `DATA_DIR` и свободное место: оригиналы сохраняются без уменьшения. При повторной ошибке сопоставьте время запроса `POST /api/reports/.../photos`, HTTP-код и запись в журнале сервера. Не публикуйте содержимое фото и токены из журналов.

Два файла в `demo/` — отдельные демонстрационные фотографии **разных** автомобилей. Они заменяют прежние рисунки и не служат парой доказательств одного события. `demo/generate.py` теперь пишет рисунки под другими именами и не перезаписывает эти файлы.
