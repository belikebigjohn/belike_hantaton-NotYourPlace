# Ubuntu: gosdyma.ru

При переходе со второго фото на проверку старый клиент отправлял оба оригинала одним запросом. Управляемый прокси хостинга отклонял его с HTTP 413. Новый клиент передаёт исходные байты частями по 512 КиБ; backend собирает и проверяет SHA-256, затем сохраняет оригинал. Анализ выполняется по сохранённым снимкам без второй большой загрузки. Оба компонента нужно обновить вместе. Для этой схемы права `sudo` и доступ к настройкам прокси не нужны, если хостинг пропускает запросы меньше 512 КиБ.

1. В `.env` на Ubuntu добавьте `https://gosdyma.ru` в `ALLOWED_ORIGINS`, сохранив нужные локальные адреса и другие действующие домены. Перезапустите службу приложения, чтобы она прочитала переменную.
2. Заберите свежий `main`, соберите frontend (`cd frontend && npm ci && npm run build`) и перезапустите только процесс приложения тем способом, которым он уже запущен на хостинге. Frontend и backend должны быть из одного коммита.
3. Проверьте права записи пользователя службы в `DATA_DIR` и свободное место: оригиналы сохраняются без уменьшения. При повторной ошибке сопоставьте время запроса `POST /api/reports/.../photo-chunks/...`, HTTP-код и запись в журнале сервера. Не публикуйте содержимое фото и токены из журналов. Если хостинг ограничивает запросы ниже 512 КиБ, лимит всё-таки должен изменить его администратор.

Два файла в `demo/` — отдельные демонстрационные фотографии **разных** автомобилей. Они заменяют прежние рисунки и не служат парой доказательств одного события. `demo/generate.py` теперь пишет рисунки под другими именами и не перезаписывает эти файлы.
