# Компьютерное зрение и backend

## Реальный пайплайн

Кадры JPEG/PNG/WebP декодируются OpenCV. Проверяются сигнатура, размер до 15 МБ, число пикселей до 40 Мп, яркость и дисперсия Лапласиана на уменьшенной копии. Оригинальные байты сохраняются отдельно без повторного кодирования. Эвристика качества не заменяет детекцию.

Номер: ONNX-детектор YOLO-v9-t из официальных release `ankandrew/open-image-models`, затем **настоящие российские веса Nomeroff Net** `anpr_ocr_ru_2022_11_22_shufflenet_v2_x2_0.ckpt`. Адаптер `backend/nomeroff_ru.py` воспроизводит inference-часть NPOcrNet и CTC декодирование, загружает state_dict безопасным weights-only loader с инертным объектом метаданных. Обучение и Lightning не нужны для запуска. Текст нормализуется в допустимые русские символы, но регулярное выражение не повышает score и не выдумывает символы. **Детекция и OCR независимо запускаются на обоих кадрах** — общем плане `scene` и крупном плане `plate`. Несколько найденных номеров возвращаются кандидатами; наличие нескольких кандидатов на одном снимке требует проверки человеком.

`plates_by_photo.scene` и `plates_by_photo.plate` содержат собственные `value`, `confidence`, `bbox`, `needs_review`, `candidates` и `photo_id`. Все рамки и кандидаты относятся только к исходному снимку. `plate_comparison.status` принимает `match`/`mismatch` только при единственном кандидате правильного формата с score не ниже 0.9 на каждом кадре и успешном завершении обоих анализов. Низкий score, отсутствие номера, несколько кандидатов или частичный сбой дают `needs_review`. Сравниваются нормализованные строки; это не проверка владельца или юридических обстоятельств. Совместимый верхний `plate` рекомендует номер с крупного плана, при пустом результате — с общего, указывает его `photo_id` и содержит объединённый список кандидатов обоих снимков без потери альтернатив. Рамка общего плана не переносится на крупный кадр. Не-конечные/вне диапазона значения score заменяются на `null` и требуют проверки.

Дорожные знаки: скачаны веса `best.pt` из Drive-папки, на которую ссылается README `DL-teammm/road_signs_recognition`. Проверено, что файл содержит **146 классов** и порядок соответствует `DL-teammm/web_service/model_info/class_labels.yaml` (названия в checkpoint без точек): индекс 34 → 6.4, индекс 138 → 8.17. Перед использованием проводится проверка всей последовательности классов, а не только числа классов. `detected` возвращается только для пространственно связанной пары на одном снимке: табличка под парковочным знаком, достаточное горизонтальное перекрытие и разумный зазор. Два знака в разных частях кадра не объединяются. После успешного инференса без целевых объектов на технически пригодном кадре возвращается `not_detected` — «не обнаружено на этом снимке». При сбое/отсутствии модели, плохом кадре, единственном знаке или пространственно несвязанной паре результат `unknown`. Эти состояния описывают только проверку классов 6.4/8.17, не отсутствие всех возможных обозначений и не законность парковки.

Моделей разметки с коляской и отдельного знака под стеклом в этих весах не подтверждено. Они возвращают `unknown`; отсутствие знака 8.17 на кадре также не даёт юридического вывода. Автомобиль и область действия знака человек проверяет на общем плане. Связывание объектов разных автомобилей сейчас не реализовано; при нескольких номерах требуется выбор/ручная проверка, знак под стеклом не присваивается никакому автомобилю автоматически.

## Источники и лицензии

- [Nomeroff Net](https://github.com/ria-com/nomeroff-net), GPL-3.0; inference-адаптер содержит атрибуцию. [Registry RU](https://models.vsp.net.ua/config_model/nomeroff-net-ocr-ru/model-shufflenet_v2_x2_0-2.json) содержит ссылку на скачанный checkpoint, алфавит и геометрию. Число accuracy в registry является заявлением авторов, не нашей метрикой.
- [FastALPR](https://github.com/ankandrew/fast-alpr), MIT; используется только как связка детектора и нашего адаптера OCR. [Open-image-models](https://github.com/ankandrew/open-image-models) — источник детектора ONNX.
- [DL-teammm](https://github.com/DL-teammm/road_signs_recognition), [matching labels](https://raw.githubusercontent.com/DL-teammm/web_service/main/model_info/class_labels.yaml). В открытом README есть веса, но явная отдельная лицензия этих весов/данных не найдена. До публичного распространения запросить разрешение авторов. Ultralytics — AGPL-3.0 или коммерческая лицензия. Скачанный checkpoint использует сериализованный PyTorch-модуль; не заменять файл непроверенными весами.

Команды скачивания — `models/setup_models.py`. Версии Python-пакетов закреплены в `backend/requirements.txt`. SHA-256 — `models/checksums.reference.json`, результат повторного скачивания — `checksums.local.json`. Большие веса и исходные фото в git не включаются.

## Запуск и хранение

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

`GET /api/health` сообщает состояние моделей. Загружаются один раз при старте. При недоступной модели `analyze` сохраняет возможность ручной проверки, не возвращает выдуманный успех. Mock-инференса в приложении нет; `DEMO_MODE=1` — флаг маркировки, который не подменяет результаты.

SQLite хранит записи с owner-хешем случайного токена HttpOnly session cookie; файлы выдаются только через проверяющие владельца endpoints, чужой владелец получает 404. Cookie SameSite=Strict; для HTTPS установить `COOKIE_SECURE=1`. Хранилище `DATA_DIR` по умолчанию `runtime-data/`; фотографии не зашифрованы на диске. Сессия 30 дней, очистка cookie теряет доступ. Для публичного сервиса нужны полноценное восстановление доступа, политика хранения и эксплуатационная проверка. Удаление записи удаляет оригиналы всех её версий. Пересъёмка сохраняет старый оригинал отдельно и в одной транзакции сбрасывает подтверждение, заявление и анализ. Источник камеры и ISO-время кадра сохраняются как сведения устройства, не заверенные сервером; импортированному файлу время съёмки не присваивается. Размеры изображения проверяются по заголовку до полного декодирования. Повторный экспорт не создаёт новую запись.

`POST /api/reports` поддерживает необязательный заголовок `Idempotency-Key` с UUID. Пара «владелец + ключ» и запись создаются в одной SQLite-транзакции; повторный и конкурентный запрос возвращают прежнюю запись без перезаписи. Для другого владельца тот же ключ создаёт отдельную запись. При удалении записи mapping удаляется каскадно. Клиент сначала получает cookie-сессию через health, затем сохраняет свой UUID черновика для повторных попыток. Это защищает от дублей после потери ответа сервера внутри той же сессии.

Reverse-geocoder поддерживает Photon GeoJSON (`GEOCODER_PROVIDER=photon`) и Nominatim JSON (`GEOCODER_PROVIDER=nominatim`), но **внешний сервис по умолчанию отключён**: задаются `GEOCODER_URL`, `GEOCODER_ENABLED=1` и контактный `GEOCODER_USER_AGENT` после выбора оператором разрешённого провайдера или собственного сервера. Запросы ограничены до одного за 1.1 секунды и кэшируются в процессе. [Photon README](https://github.com/komoot/photon#demo-server) разрешает умеренное использование публичного `https://photon.komoot.io/reverse`, без гарантии доступности и с необходимостью своего сервера при большей нагрузке. На публичной тестовой точке Берлина из API-документации получен реальный GeoJSON (Germany, Berlin, Mitte); это проверка сервиса, не координаты пользователя. [Политика публичного Nominatim](https://operations.osmfoundation.org/policies/nominatim/) требует осознанного выбора разработчиком, идентифицирующий User-Agent, атрибуцию и общий лимит 1 запрос/сек. Ошибка или отсутствие конфигурации даёт ручной ввод; фотографии наружу не передаются. Автоматическое включение Photon было отклонено автоматической проверкой разрешений из-за передачи будущих координат внешнему сервису без указания пользователем конкретного получателя; провайдер подключается явно.

## Проверки и границы

Тесты `python -m pytest tests/backend -q`: 33 проверки CRUD, исходных байтов и SHA-256, ZIP/DOCX, изоляции двух cookie-сессий, чужого Origin, атомарности невалидной пары фото, пересъёмки, источника и времени фото, ручного адреса, ошибок изображения, нормализации номера, низкой уверенности/частичного сбоя OCR, трёх состояний знаков, пространственной связи и конкурентного повторного создания. Проверяются два отдельных вызова OCR, совпадающие/разные номера, один нечитаемый кадр, несколько кандидатов на любом кадре и сохранение происхождения рамок. В Windows sandbox тестовый asyncio socketpair может блокироваться до начала приложения; запуск в разрешённом локальном окружении устраняет ограничение.

`python -m backend.verify_models` запускает **реальные модели** и сохраняет `docs/model-smoke-results.json`. Проверка на upstream crop `Е300ЕУ763` даёт полный правильный номер. Синтетический демонстрационный рисунок распознаётся неверно, это зарегистрированная ошибка, которую UI предлагает исправить. Upstream пример мог использоваться при обучении, поэтому этот тест не является независимой оценкой точности. Отдельной уличной выборки с бликами/ночью/снегом и ground truth нет: precision/recall, точность полного номера на новых реальных данных и время пользовательского пути пока не измерены. Синтетика не представляется уличной валидацией.

После включения OCR обоих кадров проведён повторный реальный smoke на CPU этого Windows-окружения без загрузки новых весов: синтетические `demo/overview-demo.png` + `demo/plate-demo.png` дали разные ошибочные строки (`А001АА88` и `А814АВВ1`) и `needs_review`, 641 мс; upstream RU crop + публичный пример авторов с несколькими иностранными машинами дали `needs_review`, 327 мс; один upstream RU crop, переданный в оба входа как техническая проверка согласованности, дал `match`, 271 мс. Эти значения — разовые измерения прогретого инференса, не пользовательского пути и не независимой уличной точности. На синтетике встречается неверный номер даже с высоким score: порог 0.9 не заменяет визуальную проверку человеком.


### Согласие на адресный поиск в текущем интерфейсе

На экране места отдельный checkbox явно называет Photon (komoot) и передачу координат. Без него браузер не вызывает геокодер, а сервер отклоняет внешнее обращение без consent=true. Только после этого выбора клиент передаёт provider=photon. URL можно заменить через PHOTON_URL. Операторские Nominatim-настройки тоже не обходят необходимость согласия. Автоматически включать передачу координат без выбора пользователя нельзя. Публичный Photon предназначен для умеренной нагрузки, для внедрения нужен подходящий провайдер.

## Мелкая табличка и фрагмент региона

Добавлен резервный поиск, если основной проход не прочитал полный номер: 9 перекрывающихся половинных окон, не более 12 различных областей для OCR. Если детектор находит почти квадратный фрагмент (например, регион), его положение и высота используются для двух более широких обрезок. Ни буквы, ни регион из геометрии не подставляются: два фактических OCR-чтения должны совпасть целиком, соответствовать формату и иметь исходную оценку не ниже 0,9. Дубли одного номера объединяются, координаты возвращаются к исходному снимку. Оценка детектора для восстановленной полной рамки отсутствует (`null`), результат всегда требует проверки человеком.

На присланном пользователем скриншоте проверена только область самой фотографии, без интерфейса приложения. Обычный проход не находил номер; новый резервный проход прочитал его правильно на обоих типах входа. Координаты самой таблички вручную не задавались. Личная фотография, её копии и госномер не включены в репозиторий. Это проверка одного конкретного сбоя, не оценка общей точности. На прежней выборке AUTO.RIA результат крупного плана остался 60/60. Воспроизводимый baseline отключает новый резервный поиск, чтобы сравнение с прежней цепочкой оставалось корректным.

## Крупная табличка, которую не замечает детектор

После повторного воспроизведения на двух новых кадрах добавлен независимый геометрический резервный поиск: OpenCV находит длинные почти горизонтальные границы, группирует соосные отрезки и составляет не более 24 областей с пропорциями таблички. Результат принимается только после совпадения полного OCR-чтения минимум на трёх различных областях с исходной оценкой от 0,93. Резервный проход запускается, если обычный и мелкомасштабный поиск не дали полного номера. Веса не изменялись, номер не зашит в код; новые результаты помечаются source=geometric_plate_recovery и требуют подтверждения человеком.

Проверка двух пользовательских примеров прошла через HTTP /api/analyze (200, оба номера прочитаны верно), затем через реальный браузер: новая фиксация → загрузка двух кадров → анализ → оба поля заполнены автоматически, номера совпадают. Использовались области фотографий из присланных скриншотов целиком; координаты таблички не задавались. Снимок результата хранится только в игнорируемой .runtime, личные фотографии и номер не публикуются в Git. Это подтверждение конкретного исправления на двух кадрах, не гарантия чтения любого номера.

### Рабочий адресный поиск: Nominatim

Photon на момент диагностики отвечал HTTP 403 как с параметром языка, так и без него. Это был отказ внешнего сервиса, а не ошибка GPS: координаты уже были получены. После явного информированного выбора владельца приложения подключён Nominatim (OpenStreetMap). Новый клиент отправляет provider=nominatim только при установленном checkbox, который прямо называет получателя координат. Старый provider=photon сохранён для совместимости; автоматической передачи новому сервису по старому согласию нет.

Публичный Nominatim используется только по действию человека, не для автодополнения: запросы сериализованы и ограничены интервалом 1,1 с, успешные результаты кэшируются, User-Agent идентифицирует приложение публичной ссылкой на репозиторий, атрибуция отображается. Endpoint заменяется через NOMINATIM_URL без правки кода. Для нескольких процессов/реплик нужен общий лимитер или собственный/договорный геокодер. Умеренное использование согласовано с владельцем; правила: https://operations.osmfoundation.org/policies/nominatim/.

Кнопка «Найти адрес по координатам» использует уже имеющиеся координаты, не повторяя запрос GPS. «Обновить координаты» запрашивает новое положение. Ошибка связи отличена от отсутствия результата; пустое поле больше не сопровождается только предложением проверить его. Новые адреса требуют проверки человеком перед продолжением.

Реальная проверка через работающий API: координаты из пользовательского скриншота дали HTTP 200 и непустой адрес; личные координаты и результат сохранены только в игнорируемой .runtime. Дополнительно в браузере использована публичная точка центра Екатеринбурга: после нового согласия адрес автоматически заполнился в поле. Скриншот docs/screenshots/address-autofill.jpg содержит эту публичную тестовую точку. 54 Python-теста и 23 frontend-теста прошли; типы, линтер и production build проверены.
