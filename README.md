## Отправка изменений в два репозитория

В текущем checkout `origin` указывает на GitHub, `gitlab` — на GitLab. После проверенного коммита выполните `./scripts/push-all.ps1`: скрипт отправляет текущую ветку в оба remote и сообщает о частичном сбое, не скрывая его. Он не добавляет файлы и не делает коммит автоматически. Для нового clone второй remote добавляется командой:

```powershell
git remote add gitlab https://gitlab.hackathon.uriit.ru/belikebigjohn/vibeclaude-notyourplace.git
```

GitHub и GitLab требуют отдельного настроенного доступа. Если один push не прошёл, после настройки доступа можно повторить скрипт — уже отправленный коммит не дублируется.

## Запуск в текущей папке

Зависимости и веса уже установлены локально. Нужны Node 20.19+ / 22.12+ / 24 и Python 3.11–3.12. Системный Python 3.15 для ML-зависимостей не подходит.

```powershell
npm run build
npm start
```

Откройте http://127.0.0.1:8000 — собранный frontend и API с одного адреса. Разработка: `npm run dev`, интерфейс http://127.0.0.1:5173. Остановка — Ctrl+C в терминале запуска. На Windows фоновый запуск: .\scripts\start-local.ps1, остановка: .\scripts\stop-local.ps1. При занятом порте остановите предыдущий экземпляр.

## Установка с нуля

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
npm --prefix frontend ci
.\.venv\Scripts\python.exe models/setup_models.py
.\.venv\Scripts\python.exe -m backend.verify_models
npm run build
npm start
```

В текущей среде .venv создано из Python 3.12, поставляемого с Codex. На другом компьютере установите Python 3.11/3.12. Ключей не требуется. Root-команды читают .env по образцу .env.example. Веса скачиваются setup-скриптом, не входят в Git; интернет нужен при установке. Для камеры физического телефона нужен HTTPS; localhost поддерживается браузерами.

## Реальные возможности

- React/Vite/TypeScript, восемь экранов по референсу, мобильная и десктопная композиция, крупные подписи и действия.
- Камера, галерея, пересъёмка, освобождение потока, локальный черновик IndexedDB при сбое сети.
- OpenCV: содержимое и качество кадров; ONNX-детектор номера + русская OCR-модель Nomeroff Net; YOLO дорожных знаков DL-teammm, классы 6.4/8.17 и проверка пространственной пары.
- Рамки обнаружений, исправление номера и подтверждение человеком. Юридического вывода нет.
- Координаты устройства; Photon reverse geocoding только после отдельного согласия на передачу координат. Без согласия адрес вводит человек. Данные адресов © OpenStreetMap contributors. Публичный Photon не гарантирует доступность; для нагрузки нужен собственный/договорный провайдер.
- SQLite и неизменные оригиналы на сервере; HttpOnly session cookie, закрытые фотографии, удаление всех версий; повторный экспорт не создаёт новую запись.
- Редактируемый проект обращения, реквизиты получателя/заявителя, DOCX (Times New Roman 14 пт), TXT, HTML, оригиналы, manifest SHA-256 и инструкция в ZIP.
- Личная история: черновик, пакет готов, экспортирован, отправлено вручную. Последнюю отметку ставит пользователь.

## Ограничения

Разметка и знак под стеклом пока возвращают unknown: модели не подтверждены. Нет привязки нескольких машин к знакам под стеклом. Модель дорожных знаков выполняет инференс, но независимые precision/recall на уличной выборке не измерены. Физический телефон, GPS устройства, MAX и реальная подача не проверены. Цель 60–90 секунд не измерена.

Session cookie — не полноценная учётная запись. Очистка cookie лишает доступа к серверным материалам; для публичного запуска нужны сроки хранения, авторизация, HTTPS и защита от злоупотреблений. IndexedDB может быть очищена браузером. Фотографии обрабатываются сервером сервиса, координаты передаются геокодеру только по отдельному выбору. Автоподачи нет.

Лицензии: Nomeroff GPL-3.0, FastALPR MIT, Ultralytics AGPL-3.0/коммерческая. Отдельная лицензия весов DL-teammm не найдена; условия распространения надо уточнить до публикации. Отладочные сведения находятся в документации, не в основном сценарии.

На шаге места работает встроенная Яндекс Карта с маркером координат. Выбор точки кликом и геокодирование подготовлены для подключения `YANDEX_MAPS_API_KEY`; без ключа доступны виджет, переход в Яндекс Карты и ручное уточнение координат. [Настройка и границы проверки](docs/YANDEX_MAPS.md).

Повторная проверка: добавлены выбор кандидата номера с соответствующей рамкой, подсказки качества каждого кадра, устойчивое сохранение без дублей через Idempotency-Key и повторное подтверждение при изменении фактов. Сквозной тест работающего API: `.venv\Scripts\python.exe scripts/integration_smoke.py`; результат в docs/integration-smoke-results.json. Используются только синтетические материалы, запись теста удаляется автоматически. Скрипт проверяет два экспорта, оригиналы, хеши, одну запись в истории, закрытость фото и необходимость согласия для геокодирования.

Последняя мобильная проверка: OCR отдельно на общем и крупном фото, выбор кандидатов привязан к своему снимку. Разные номера блокируют продолжение в интерфейсе и подготовку пакета на сервере. После ручной сверки обоих номеров в браузере пройден путь до готового пакета и повторного открытия из истории. Главная проверена при ширине 360, 390 и 430 px без горизонтального переполнения. Новая иллюстрация, точное центрирование CTA, контрастные рамки и ограниченные анимации описаны в docs/UI.md; происхождение изображения — docs/HERO_ASSET.md.
